# Костыли и особенности проекта 2MOV

## 1. Закрытие чата через 15 секунд после завершения заказа

**Проблема:** Если закрыть чат сразу после завершения заказа, клиент может не получить последнее уведомление.

**Решение:** В `bot-driver/main.go` в функции `completeOrder` добавлена горутина, закрывающая чат через 15 секунд.

``
go func() {
    time.Sleep(15 * time.Second)
    db.Collection("chats").UpdateOne(...)
}()
``

**Планируемое улучшение:** Закрывать чат только после подтверждения доставки сообщения.

---

## 2. Два активных чата при одном заказе

**Проблема:** Иногда в коллекции `chats` висят старые чаты со статусом `active` (например, после перезапуска ботов).

**Решение:** 
- При завершении заказа чат закрывается через 15 секунд.
- При создании нового заказа всегда создаётся новый чат.

**Планируемое улучшение:** Добавить автоматическую очистку старых чатов при старте бота (или раз в сутки).

## 3. Callback-кнопки требуют ответа через `POST /answers`

**Проблема:** При нажатии на callback-кнопку MAX ожидает ответ, иначе кнопка «зависает».

**Решение:** В обработчике callback обязательно отправляется `POST /answers`.

``
answerURL := fmt.Sprintf("https://platform-api.max.ru/answers?callback_id=`s", callbackID)
answerBody := map[string]interface{}{"notification": "✅"}
``

**Планируемое улучшение:** Отправлять более информативные уведомления.

## 5. Клиент и водитель — один пользователь при тестировании

**Проблема:** При тестировании на одном аккаунте `driver_id` и `client_id` совпадают, чат работает как «эхо».

**Решение:** В production использовать разных пользователей MAX. При тестировании создавать двух разных пользователей.

## 6. MQTT — вместо тикеров и MongoDB для сообщений

**Проблема:** Тикеры (3 секунды) создавали задержки и лишнюю нагрузку на MongoDB.

**Решение:** Внедрён MQTT брокер (Mosquitto). Все сообщения между ботами идут через MQTT мгновенно.

**Топики:**
- `chat/{userID}` — текстовые сообщения
- `status/{userID}` — статусы заказов (accepted, at_pickup, to_delivery, at_delivery, completed)

**Мост:** MQTT bridge между серверами (FirstVDS ↔ HostVDS) для Telegram-бота.

**Безопасность:** Доступ к MQTT ограничен iptables (только localhost и IP второго сервера).

---

## 7. Два активных заказа у водителя — выбор заказа

**Проблема:** Если у водителя несколько активных заказов, сообщения уходят в первый попавшийся (или никуда).

**Решение:** 
- Определяются все активные заказы водителя.
- Если заказ один — сообщение отправляется автоматически.
- Если заказов несколько — показываются кнопки для выбора заказа.

**Планируемое улучшение:** Запоминать выбранный заказ в сессии (`driver_sessions`).

---

## 8. Клиентский бот не получает сообщения от водителя (было)

**Проблема:** После перехода на MQTT клиентский MAX-бот не подписывался на топик `chat/+`.

**Решение:** Добавлена подписка на `chat/+` в `main.go` клиентского бота.

``
mqttClient.Subscribe("chat/+", 1, func(c mqtt.Client, m mqtt.Message) {
    parts := strings.Split(m.Topic(), "/")
    if len(parts) == 2 {
        clientID := parts[1]
        sendMaxMessage(token, clientID, string(m.Payload()))
    }
})
``

## 9. Telegram-бот получает сообщения для MAX-клиентов (было)

**Проблема:** Telegram-бот подписан на `chat/+` и пытается отправить сообщения пользователям, у которых нет Telegram ID.

**Решение:** Добавлена проверка: сообщение отправляется только если `userID` совпадает с `telegram_id` в коллекции `users`.

``
var user User
err := db.Collection("users").FindOne(ctx, bson.M{"telegram_id": userID}).Decode(&user)
if err == nil {
    sendMessage(bot, tgChatID, text)
}
``

## 12. Ограничение доступа к MQTT через iptables

**Проблема:** Mosquitto не поддерживает фильтрацию по IP.

**Решение:** Доступ к порту 1883 ограничен через iptables (только localhost и IP второго сервера).

``
iptables -A INPUT -p tcp --dport 1883 -s 127.0.0.1 -j ACCEPT
iptables -A INPUT -p tcp --dport 1883 -s 45.38.19.47 -j ACCEPT
iptables -A INPUT -p tcp --dport 1883 -j DROP
``

## 13. Туннель для MongoDB через SSH

**Проблема:** MongoDB на FirstVDS не доступна напрямую с HostVDS.

**Решение:** SSH-туннель, пробрасывающий порт 27017.

``
autossh -M 0 -N -L 27017:localhost:27017 -i /root/.ssh/id_tunnel tunnel@62.181.53.145
``

**Планируемое улучшение:** Добавить healthcheck и автоматический перезапуск туннеля.

---

## 14. Мост MQTT между серверами

**Проблема:** Telegram-бот (HostVDS) не мог напрямую подключиться к MQTT на FirstVDS.

**Решение:** Mosquitto на HostVDS настроен как мост (bridge) к брокеру на FirstVDS.

``
connection firstvds
address 62.181.53.145:1883
topic # both 0
cleansession true
``

**Планируемое улучшение:** Настроить аутентификацию для моста.
