# Костыли проекта 2MOV

## 1. Закрытие чата через 15 секунд после завершения заказа

**Проблема:** Если закрыть чат сразу после завершения заказа, клиент может не получить последнее уведомление («Заказ выполнен»), потому что клиентский бот проверяет только активные чаты.

**Решение:** В `bot-driver/main.go` в функции `completeOrder` добавлена горутина, которая закрывает чат через 15 секунд:

```
go func() {
    time.Sleep(15 * time.Second)
    db.Collection("chats").UpdateOne(...)
}()
```

**Почему не зависает бот:** `go func()` запускает код в отдельной горутине, основной поток продолжает работу.

**Планируемое улучшение:** Закрывать чат после того, как сообщение о завершении получило статус `delivered`.

## 2. Фоновая проверка сообщений вместо вебхуков

**Проблема:** MAX не поддерживает прямую отправку сообщений от одного бота другому. Чат между клиентом и водителем работает через общую MongoDB.

**Решение:** Клиентский и водительский боты раз в 3 секунды проверяют БД на наличие новых сообщений для своих пользователей.

```
ticker := time.NewTicker(3 * time.Second)
for range ticker.C {
    // проверка БД
}
```

**Почему 3 секунды:** Баланс между задержкой доставки и нагрузкой на БД.

**Планируемое улучшение:** Перейти на WebSocket или Redis Pub/Sub при росте нагрузки.

## 3. Два активных чата при одном заказе

**Проблема:** Иногда в коллекции `chats` висят старые чаты со статусом `active`, что приводит к дублированию сообщений или отправке не тому пользователю.

**Решение:** При завершении заказа чат закрывается через 15 секунд. При создании нового заказа всегда создаётся новый чат.

**Планируемое улучшение:** Добавить автоматическую очистку старых чатов при старте бота.

---

## 4. Callback-кнопки требуют ответа через `POST /answers`

**Проблема:** При нажатии на callback-кнопку MAX ожидает ответ, иначе кнопка «зависает».

**Решение:** В обработчике callback обязательно отправляется `POST /answers`:

```
answerURL := fmt.Sprintf("https://platform-api.max.ru/answers?callback_id=%s", callbackID)
answerBody := map[string]interface{}{"notification": "✅"}
```

**Планируемое улучшение:** Отправлять более информативные уведомления.

---

## 5. Геолокация не работает через кнопку `request_location`

**Проблема:** MAX Bot API не поддерживает кнопку запроса геолокации в том виде, в котором мы пытались.

**Решение:** Пользователь отправляет геолокацию вручную через стандартное меню вложения MAX.

**Планируемое улучшение:** Дождаться официальной поддержки или использовать мини-приложения.

---

## 6. Клиент и водитель — один пользователь при тестировании

**Проблема:** При тестировании на одном аккаунте `driver_id` и `client_id` совпадают, чат работает как «эхо».

**Решение:** В production использовать разных пользователей. При тестировании создавать двух разных пользователей MAX.

**Планируемое улучшение:** Добавить режим симуляции для разработки.
