# Архитектура 2MOV

## Общая схема

Пользователи (MAX) → Caddy (reverse proxy) → Боты (Go) → MongoDB

## Компоненты

| Компонент | Роль | Где |
|-----------|------|-----|
| **Caddy** | Веб-сервер, SSL, проксирование запросов `/webhook` и `/webhookd` | FirstVDS |
| **Клиентский бот** | Принимает заказы от клиентов, сохраняет в MongoDB | FirstVDS |
| **Водительский бот** | Принимает заказы от водителей, обновляет статус | FirstVDS |
| **MongoDB** | Хранит пользователей, заказы, рейтинги | FirstVDS |
| **SSH-туннель** (для Telegram) | Соединяет HostVDS с FirstVDS | HostVDS → FirstVDS |

## Потоки данных

### Клиентский сценарий
1. Клиент пишет боту `/order` в MAX
2. MAX присылает вебхук на `https://2mov.ru/webhook`
3. Caddy проксирует запрос на `bot:8080`
4. Клиентский бот обрабатывает команду, сохраняет заказ в MongoDB
5. Бот ищет свободных водителей (в разработке)

### Водительский сценарий
1. Водитель пишет боту `/accept` в MAX
2. MAX присылает вебхук на `https://2mov.ru/webhookd`
3. Caddy проксирует запрос на `bot-driver:8080`
4. Водительский бот обновляет статус заказа в MongoDB
