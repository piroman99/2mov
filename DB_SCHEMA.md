# Схема базы данных 2MOV

## Коллекция `users`
| Поле | Тип | Пример | Описание |
|------|-----|--------|----------|
| `telegram_id` | string | `"164004252"` | Telegram ID (если пользователь из Telegram) |
| `max_user_id` | number | `5082630` | MAX ID (если пользователь из MAX) |
| `first_name` | string | `"Иван"` | Имя |
| `last_name` | string | `"Карпухин"` | Фамилия |
| `rating` | number | `5.0` | Рейтинг |
| `trips_count` | number | `25` | Кол-во поездок (как водитель) |
| `role` | string | `"client"` | Роль (`client`/`driver`) |
| `created_at` | Date | `...` | Дата регистрации |
| `last_active_at` | Date | `...` | Последняя активность |

## Коллекция `orders`
| Поле | Тип | Пример | Описание |
|------|-----|--------|----------|
| `_id` | string | `"1779942729382293525"` | ID заказа |
| `client_id` | string | `"164004252"` | ID клиента (всегда строка) |
| `driver_id` | string | `"5082630"` | ID водителя |
| `status` | string | `"pending"` | Статус заказа |
| `price` | number | `200` | Цена |
| ... | ... | ... | остальные поля |

## Коллекция `chats` (проблемная)
| Поле | Тип | Пример | Проблема |
|------|-----|--------|----------|
| `client_id` | **number или string?** | `164004252` | В MAX-чатах — число, в Telegram — строка |

## Коллекция `chat_messages`
| Поле | Тип | Пример | Описание |
|------|-----|--------|----------|
| `to_user` | string | `"client_164004252"` | Получатель (с префиксом `client_` или `driver_`) |
| `status` | string | `"pending"` | `pending` / `delivered` |

## 🔴 Известные проблемы
1. `client_id` в `chats` хранится в разных типах (число/строка)
2. Нет поля `platform` в `users` (MAX vs Telegram)
